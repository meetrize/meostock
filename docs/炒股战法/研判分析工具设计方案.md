# 全面研判分析工具 — 产品与交互设计方案

> 依据：[股票投资入门知识体系与研判方法论](./股票投资入门知识体系与研判方法论.md)  
> 精简总览：[研判工具设计-交互总览](./研判工具设计-交互总览.md)（与设计 Canvas 同内容，便于快速扫读）  
> 工程计划：[dev-plan-research-workbench.md](../dev-plan-research-workbench.md)  
> 目标：把方法论中**一切可量化 / 可结构化**的研判维度，做成统一工作台；消息与新闻借助 AI 汇总，输出**方向性结论 + 证据链**，而非「荐股黑箱」。  
> 落地底座：现有 `stock-dashboard` Portal / Workspaces、行情缓存、Tushare topic、大盘云图、`/agent`、新闻与日历 API。  
> 本文为产品设计，**不构成投资建议**。

> **文档定位（v2.1）**：本文是三份文档中的**单一事实源（single source of truth）**；交互总览只做导航与摘要，方法论文档是理论总纲，工程计划负责任务拆解与挂载点。三处产品内容如有冲突，以本文为准。本文受众为产品与工程人员；零基础投资者请先读方法论文档。

## 0. 一句话定位

**Research Workbench（研判工作台）**：一条自上而下的分析流水线——

```text
宏观 Regime → A股大盘温度 → 板块/概念轮动 → 个股多维研判 → 交易卡片（假设/证据/仓位/退出）
```

每一层都输出：

| 输出 | 含义 |
|---|---|
| **状态标签** | 偏多 / 中性 / 偏空 / 数据不足 |
| **量化分数** | 0–100 或分位数（可解释） |
| **证据列表** | 指标值 + 时间戳 + 数据源 |
| **AI 摘要** | 方向性叙述（可折叠、可追问） |
| **下一步动作** | 钻取到下一层 / 加入观察池 / 生成交易卡片 |

## 1. 设计原则

1. **证据优先于结论**：任何 AI 方向句旁必须挂可点击的原始指标或原文链接。
2. **分层不混层**：宏观结论不直接变成「买某只股」；个股结论必须带回所属板块与大盘上下文。
3. **规则分 + AI 分分离显示**：规则引擎打「硬分」，AI 打「叙事置信度」，禁止混成一个神秘总分误导。
4. **工作区可编排**：复用现有 12 列 Portal；不同策略用不同 Workspace 预设（长线桌 / 波段桌 / 短线桌）。
5. **先纪律后阿尔法**：MVP 先做扫描、对比、日志、复盘与**最小风控**，再做预测类模型；完整风控不得拖到最后一期（见 §10）。
6. **统一对象模型**：`Scope`（宏观 / 市场 / 板块 / 个股）+ `Signal` + `Evidence` + `Note`，全站导航与 Agent 共用。
7. **数据可得性优先于指标丰富度**：任何指标先确认数据源、频率与口径，不可得则显式标注，禁止用已停更数据充当实时信号（见 §9.1）。

## 2. 方法论 → 模块映射

| 方法论层级 | 工具模块 ID | 核心问题 | 量化 / 结构化手段 | AI 角色 |
|---|---|---|---|---|
| L2 宏观与流动性 | `M.macro` | 现在偏进攻还是防守？ | 利率、信用、通胀、汇率、风险偏好代理 | 汇总政策/海外冲击，输出 Regime 叙事 |
| **L1（制度）+ L6（资金）** | `M.market` | A 股整体温度？ | 涨跌家数、涨停跌停、成交额分位、**两融余额变化、成交额、ETF 申赎、主力大单估算** | 解读「冰点/升温/过热」阶段 |
| L3 产业与景气 | `M.industry` | 哪些行业景气向上？ | 行业指数相对强度、资金流、估值分位、景气代理 | 产业链新闻 → 景气方向 |
| 板块 / 概念（跨 L3/L6） | `M.theme` | 主线题材是什么？ | 板块涨幅、连板高度、成分扩散、资金净流入 | 题材逻辑提炼与生命周期判断 |
| **跨层（L3/L6）＋路径 D** | `S.event` + `M.sentiment` | 有何催化？情绪过热吗？ | 公告分类、新闻情感、涨停溢价、龙虎榜 | 事件聚类、利多利空方向与时效 |
| L4 公司基本面 | `S.business` + `S.fina` | 靠什么赚钱？质量如何？ | ROE、毛利率、现金流、负债、同业对比 | 商业模式一页纸 + 风险点 |
| L5 估值与预期 | `S.valuation` | 贵还是便宜？ | PE/PB/PS/股息率历史分位、同业、PEG | 预期差口述（需标注来源） |
| L6 趋势 / 波段 / 量价 | `S.tech` | 趋势完好吗？买点在哪？ | MA、动量、波动、量价背离、波段结构 | 用白话解释技术状态（不编造信号） |
| **L7 组合与执行** | `P.card` + `P.journal` + `P.portfolio` | 买多少、错了怎么办？ | 仓位模板、止损线、日志字段、**组合暴露/集中度/再平衡** | 根据模板生成交易卡片草稿、偏差归因 |

### 2.1 层级映射说明（v2 澄清）

- **事件 / 情绪不是七层中的独立层**。方法论里「事件 / 情绪」是 §4.1 的路径 D，其内容分布在 L3（产业催化）、L6（资金与价格行为）与 L7（执行纪律）之中，因此在本设计中标记为「跨层（L3/L6）＋路径 D」，而**不再占用 L7 编号**。
- **L7 唯一指向「组合、行为与执行」**，对应交易卡片、交易日志与新增的组合风控模块 `P.portfolio`。
- **大盘温度同时依赖 L1 与 L6**：涨跌停 / 交易制度属 L1，成交额、资金与情绪属 L6；原文将其整体归为「L1+」不够准确，已拆分标注。
- 若后续确需把事件 / 情绪独立成层，须**同步修订方法论文档**（七层 → 八层）与本表，禁止只改一处。

## 4. 模块详细设计

### 4.1 宏观模块 `M.macro`

**展示**

- 顶部 **Regime 条**：`紧缩/中性/宽松` × `风险偏好低/中/高`（2×2 或雷达）
- 指标卡网格：美债利率、国内利率代理、汇率、商品、日历事件临近度
- 时间轴：近 30/90 日关键宏观事件 + AI 一句话影响
- 右侧「对本周仓位含义」：仅给**总仓位倾向**（偏进攻 / 中性 / 防守），不下沉到个股

**交互**

- 点指标 → 展开历史分位图
- 「生成本周宏观简报」→ 调用 Agent，输出结构化 JSON + 可读摘要
- 一键同步到 Workspace「宏观条」面板

**数据**

- 已有：`/api/macro/rates`、日历、全球 spark
- 补齐：国内宏观序列（CPI/PMI/M2/社融/SHIBOR 等，按可得数据源分阶段）

**口径约束**

- CPI / PMI / M2 / 社融均为**月度低频**数据，须显示发布期与 `as_of`，提示陈旧风险；**禁止把月频数据包装成日频信号**。

**AI Prompt 约束**

- 必须引用具体数值与日期；禁止「一定会涨」；输出字段：`regime`、`drivers[]`、`risks[]`、`position_bias`、`confidence`

### 4.2 A 股大盘模块 `M.market`

**展示（「市场温度计」）**

| 区块 | 内容 |
|---|---|
| 温度综合 | 0–100 温度分 + 情绪阶段标签（启动/主升/分歧/退潮/冰点） |
| 宽度 | 涨跌家数、涨停/跌停、炸板率、连板高度分布 |
| 成交 | 两市成交额及 20/60 日分位 |
| 资金 | **两融余额及变化、沪深港通成交总额（非净额）、ETF 申赎、主力大单净流入（须标注为估算口径）** |
| 风格 | 大盘/小盘、价值/成长相对强度 |
| AI 解读 | 「今日大盘一句话 + 三点证据」 |

> **v2 重要更正**：北向资金**日度净买入序列已于 2024-08-16/19 断档**（2024-05-13 起取消盘中实时披露，2024-08-19 起盘后不再披露每日净买入，改为季度披露持股；盘后仍公布成交总额、成交笔数、ETF 成交额及前十大活跃证券）。因此北向**不得进入日频温度分公式**，只保留季度持股变动作为慢变量参考。任何仍显示「今日北向净流入」的视图都必须下线或改为成交额口径。

**交互**

- 温度分可下钻到贡献因子（哪些指标把分拉高/拉低）
- 点击「情绪阶段」→ 展示阶段定义与历史相似日（标注为**实验性 / 可选**，避免为相似日检索引入过拟合与范围蔓延）
- 跳转大盘云图 `/dapan/`、复盘 `/fupan`

**量化建议（示例规则，可配置）**

```text
温度分 ≈ w1*涨跌比分位 + w2*涨停质量 + w3*成交额分位
        + w4*两融/主力资金估算 + w5*(1-波动惩罚)
情绪阶段：由连板高度、晋级率、炸板率、指数位置规则机判定
```

> 涨停质量、连板高度等因子须按板块区分涨跌停幅度（见 §9.1）。

### 4.3 板块 / 概念模块 `M.industry` + `M.theme`

**展示**

- **轮动热力**：行业 × 周期（日/周/月）相对强度矩阵
- **主线看板**：今日/本周 Top 板块（涨幅、资金、扩散度、估值分位）
- **概念生命周期**：萌芽 → 发酵 → 高潮 → 退潮（规则 + AI 标签）
- **成分透视**：龙头 / 中军 / 跟风分层列表
- 嵌入或链到现有 Boards、Heatmap

**交互**

- 选中板块 → 右侧抽屉：资金曲线、估值、成分涨跌分布、相关新闻 AI 摘要
- 「对比两个板块」→ 双列相对强度 + 资金
- 「只看我的能力圈行业」过滤器
- 从板块一键「扫描成分股（套用策略模板）」

**AI**

- 输入：板块涨跌、资金、公告/新闻簇
- 输出：`theme_logic`（一句话逻辑）、`stage`、`leaders[]`、`falsify_if`（证伪条件）

### 4.4 个股六维研判页 `S.*`（核心页）

路由：`/research/s/:code` 或增强现有 `/s/:code` 的「研判」Tab。

#### 页头（始终可见）

```text
[代码 名称] 行业/概念标签  |  现价 涨跌  |  六维状态 pill（随策略模板）
[加入观察池] [生成交易卡片] [问 Agent] [对比同行]
```

#### 六维随策略模板动态启用（v2 新增）

六维不应对所有策略一视同仁。由当前 Workspace 的策略模板决定哪些维度启用、哪些灰显/隐藏：

| 维度 | 长线桌 | 波段桌 | 短线桌 |
|---|---|---|---|
| 1 商业模式（三态标签，非数值分） | 启用 | 启用 | 灰显 |
| 2 财务质量 | 启用 | 启用 | 灰显 |
| 3 估值吸引力 | 启用 | 弱启用 | 灰显 |
| 4 趋势 / 波段 | 弱启用 | 启用 | 启用 |
| 5 量价健康度 | 弱启用 | 启用 | 启用 |
| 6 事件 / 情绪 | 灰显 | 启用 | 启用（可替换为「题材辨识度/资金结构」） |

- 灰显维度仍可点击查看，但**不参与排序、不计入综合分**。
- 「总分仅用于排序，决策必须下钻证据」——且**商业模式维度本身不产出数值分**（见维 1）。

> 页面中部用 Tab 或纵向锚点展开六维详情；每条 AI 方向句均以虚线边框呈现，规则结论用实线。

#### 维 1：商业模式 `S.business`（v2 改为三态）

| 展示 | 说明 |
|---|---|
| AI 一页纸 | 赚谁的钱、怎么赚、护城河、主要风险（引用年报/官网表述） |
| 结构图 | 收入构成（若有数据）饼图 / 条形 |
| **确认状态** | 三态标签：`清晰（已人工确认）` / `存疑` / `未验证`；**不产出 0–100 分数** |

- 交互：一键「重新生成」；「引用原文」打开公告/年报片段；用户可覆盖 AI 段落并标记确认状态。
- 状态用途：`未验证` 时禁止「生成交易卡片」（与 §8、§4.6 呼应），而非把它折算成一个分数。

#### 维 2：财务 `S.fina`

| 展示 | 说明 |
|---|---|
| 质量仪表盘 | ROE、毛利率、净利率、经营现金流/净利、负债率 — 同行分位 |
| 趋势小图 | 近 3–5 年关键指标 |
| 红旗清单 | 商誉、应收账款激增、经营现金流持续为负等规则告警 |

交互：切换单季/年度；点指标看定义与公式（数据来自 `MetricDefinition`，见 §7.2）；导出到扫描条件。

#### 维 3：估值 `S.valuation`

| 展示 | 说明 |
|---|---|
| 估值表 | PE/PB/PS/股息率 当前值、5 年分位、同行中位 |
| 区间带 | 「历史分位带」上的当前点 |
| 情景 | 简单敏感度：盈利 ±20% × 估值分位变化 → 隐含价格区间（教学向） |

交互：切换 TTM/预测；加入「低估值」扫描器条件。

#### 维 4–5：趋势 / 波段 / 量价 `S.tech`

| 展示 | 说明 |
|---|---|
| 主图 | K 线 + MA + 波段标注（高低点结构，规则识别） |
| 状态机 | 上升趋势 / 震荡 / 下降；是否站上关键均线 |
| 量价 | 放量突破、缩量回踩、量价背离标记 |
| 信号条 | 复用并扩展现有 Scanner 信号，每条可「为何触发」 |

交互：切换日/周；拖选区间看波段涨跌幅；「符合我的波段模板吗？」Checklist。

#### 维 6：事件与情绪 `S.event`

| 展示 | 说明 |
|---|---|
| 事件时间线 | 公告、新闻、龙虎榜、大宗、重要股东变动 — 统一时间轴 |
| AI 事件卡 | 每簇事件：方向（利多/利空/中性）、时效（已计价/发酵中）、置信度 |
| 情绪微指标 | 近 N 日涨停关联、换手分位、新闻情感分（若有） |

交互：过滤事件类型；「今日与本票相关的全市场新闻」；追问 Agent「这对估值假设有何影响」。

### 4.5 多维扫描器 `Scanner++`

在现有 `/scanner`、`/eod-picker` 上升级：

**策略模板（预设）**

| 模板 | 条件示例（可配置） |
|---|---|
| 质量+低估值 | ROE_3y≥12%，现金流健康，PE 分位≤30%，排除 ST |
| 趋势波段 | 价>MA60，MA20>MA60，回撤自高点≤15%，成交额达标 |
| 主线低吸 | 所属板块处于发酵/主升，个股相对板块 RS 健康，非连板高潮 |
| 情绪试错 | 板块辨识度高，首板/二板规则（高风险，默认关闭） |

**成交可得性约束（v2 新增）**：扫描器须按 §9.1 的涨跌停差异处理——一字涨停 / 跌停 / 停牌标的标记为「信号成立但不可成交」，不得直接输出为可买入候选；回测同样遵守该约束。

**展示**：结果表（列=因子值）+ 六维状态 pill + 「一键打开研判页」。  
**交互**：保存策略、定时跑、推送到观察池、对比模式（最多 4 只）。

### 4.6 交易卡片与复盘 `P.card` / `P.journal`

对应方法论「统一研判模板」字段强制落库：

```yaml
symbol: "600036.SH"
thesis: "..."              # 假设
evidence: [...]            # 引用 Signal/Evidence id
pricing: "PE 分位 22%"     # 定价
upside_downside: "..."     # 赔率
position_pct: 8
stop_rule: "跌破 MA20 或逻辑证伪"
falsify_conditions: [...]  # 结构化证伪条件（v2 新增）
status: draft|open|closed|cancelled|stopped
# —— 以下为复盘所需字段（v2 新增）——
strategy_template_id: "quality_value"
entry_price: 38.60
entry_date: "2026-11-20"
target_price: 46.00
holding_period_days: 90
exit_price: null
exit_date: null
exit_reason: null          # 逻辑兑现 / 证伪触发 / 止损 / 主动平仓
pnl_pct: null
attribution_tags: []       # 行为偏差标签，见 §4.9
```

**展示**：卡片看板（草稿 / 持有 / 已结案 / 取消 / 止损出局）+ 月末复盘报表。

**复盘报表指标**：胜率、盈亏比、最大回撤、违规次数，**以及基准指数、超额收益、信息比率**（回应用户方法论 §6.3「对照基准超额」的要求；基准按策略模板选择，如沪深300/中证500/创业板指）。

**交互**：

- 从个股页「生成卡片」预填六维摘要；商业模式未确认（§4.4 维 1）时禁止生成。
- 结案时强制写「对错归因」，并**自动对照开卡时的 `falsify_conditions` 判断是否触发**，把客观证据与主观感受分开，减少事后合理化（与 §4.9 呼应）。

### 4.8 一致性检查器（v2 新增）

> 落地方法论 §4.4「基本面 / 估值 / 技术 / 组合四者一致时胜率赔率更好；冲突时减仓或放弃」。

- 输入：同一 Scope 的四组结论（基本面 `S.fina`、估值 `S.valuation`、技术资金 `S.tech`/`S.event`、组合 `P.portfolio`）。
- 规则：检测典型冲突，如「财务强但趋势弱」「估值贵但情绪热」「事件利多但估值分位已高」。
- 输出：页头与交易卡片上的「维度冲突」标记 + 冲突说明 + 卡片置信度下调。
- **边界**：只提示冲突与降低置信度，**不自动生成买卖建议**。

### 4.9 行为偏差检测（v2 新增）

> 补齐方法论 L7「行为与纪律」在产品中的缺位，是「先纪律后阿尔法」的差异化能力。

基于交易日志与持仓数据自动识别：

| 偏差 | 检测信号 |
|---|---|
| 处置效应 | 盈利持仓平均持有天数 < 亏损持仓平均持有天数 |
| 追涨杀跌 | 买入后 N 日内回补 / 高位追单占比 |
| 频繁交易 | 年化换手率、单票重复进出次数 |
| 亏损加仓 | 浮亏状态下加仓的次数与金额 |

- 输出：月度复盘中的「行为偏差报告」，关联 `attribution_tags` 写入交易卡片。
- 边界：仅做行为提示与纪律统计，不做投资建议。

| 元素 | 规则 |
|---|---|

### 5.4 AI 输出校验与合规标识（v2 新增）

把 §13「风险与对策」中承诺的数值校验落实为运行时机制：

1. **证据校验**：AI 方向句必须携带非空 `evidence_ids`，且每个 id 可解析到 `Evidence`；否则拦截，不展示方向句。
2. **数值校验**：AI 输出中的任何数值必须与 `MetricSnapshot` 一致；不一致则拦截并标记「模型输出与数据源冲突」。
3. **降级展示**：无法验证时降级为「仅供参考（未校验）」并显式标注，不得伪装成事实。
4. **合规标识**：每条 AI 输出随卡片持久化「不构成投资建议」与「数据可能延迟」提示，不只在文档页脚声明。

## 6. 交互设计

### 6.1 全局交互模式

### 6.2 关键用户流程（用例）

**用例 1：早盘 10 分钟定向**

1. 打开 `/research` → 看 Regime + 大盘温度 + 主线 Top3
2. 点主线板块 → 看生命周期与龙头
3. 对龙头开六维 → 若估值/趋势冲突（§4.8），标记「仅观察」
4. 生成/更新今日简报到 Workspace

**用例 2：自下而上研究一只股票**

1. 搜索进入个股研判页
2. 先读商业模式与财务红旗 → 估值分位 → 趋势量价 → 事件
3. 点「大盘/板块是否支持」自动带出上下文条

**用例 3：新闻冲击**

1. 日历或新闻推送进入事件轴
2. AI 聚类：「对哪些板块/个股有方向性影响」
3. 用户确认后批量刷新相关 Scope 的事件维分数
4. 不自动下单建议，只更新观察池标签

Agent 始终接收：


## 9. 数据可得性与回测验证规范（v2 新增章节）

### 9.1 指标可得性矩阵（先确认可得，再谈丰富）

| 指标 | 来源 / 频率 | 成本与限制 | 降级方案 |
|---|---|---|---|
| 行情 / K 线 / 涨跌停 | 本地缓存 / 日频 | 低 | 无数据即空态 |
| 北向资金 | **日度净买入已停更**；季度持股可查 | 2024-08-19 起披露调整 | **移出日频温度分**，仅作季度慢变量 |
| 两融余额 / 成交额 | 交易所 / 日频 | 低 | 主力大单估算替代，须标注口径 |
| 主力大单净流入 | 逐笔成交估算 / 日频 | 口径不统一 | 标注「估算」，不作为硬证据 |
| 龙虎榜 / 连板高度 / 炸板率 | `ts:limit` + 行情宽度 / 日频；龙虎榜见 `ts:top_list` | 需 Tushare topic 已同步 | 缺失则事件维标「数据未接入」 |
| 财务三表 / ROE / 现金流 | Tushare `g_research`（**现为 catalog placeholder**） | **需较高积分 / 权限**；P2 前须做权限探测 | 无权限：行情已有 PE/PB 作弱估值 + 手工导入 / 免费源；缺失走空态，禁止编造 ROE |
| CPI / PMI / M2 / 社融 | 统计发布 / 月度；catalog 中 `ts:ph:macro` 仍为占位 | 低频 | 显示发布期与 `as_of`，禁止日频化；P1 宏观桌先用已有 `/api/macro/rates` + 日历 |
| EV/EBITDA | 需专门数据源 | A 股可得性有限 | 该指标可暂不实现，用 PE/PB 替代 |
| 涨停复盘页 `/fupan` | 外链 HTML iframe | 非本库结构化数据 | **仅短线桌可视化嵌入**；情绪阶段 / 炸板率 / 连板高度的**规则分**必须基于本地 `ts:limit` + 全市场行情宽度，**禁止**解析外链 HTML 充当硬证据 |

**涨跌停制度差异（因子与回测必须区分）**：主板 ±10%、创业板/科创板 ±20%、北交所 ±30%、ST ±5%，新股上市前 5 个交易日通常无涨跌幅限制。涨停质量、连板高度、突破信号与回测成交假设均须按板块和上市状态调整；一字板 / 跌停 / 停牌标记为「信号成立但不可成交」。

### 9.2 回测与验证规范

> 落地方法论 §6.5「量化最大的坑」。任何「完美曲线」未满足以下全部条件，一律不得作为产品结论展示。

1. **日历对齐**：按交易日历对齐，`MetricSnapshot` 以 `disclose_at` 而非报告期末对齐，杜绝前视偏差。
2. **复权与重列**：价格用 `adjusted` 字段标明复权方式；财务重列用 `restated` 标记并回测重算。
3. **幸存者偏差**：历史回测须包含当期成分股（含退市 / ST），不得用当前成分倒推历史。
4. **成交约束**：计入涨跌停、停牌、一字板无法成交、最小交易单位与 T+1。
5. **成本与滑点**：佣金、印花税、过户费、滑点假设真实可配置。
6. **样本外验证**：训练 / 验证 / 测试分割 + walk-forward；样本外结果单独标注。
7. **规则版本化**：`Signal.version`、`StrategyTemplate` 版本随回测记录存档，禁止用事后调参结果冒充历史表现。
8. **实验性标记**：未完成样本外验证的规则，UI 显示「实验性」，不得进入默认预设。

## 10. 分阶段交付（v2 调整：风控前置；v2.1 对齐工程计划）

> 调整理由：原方案把「持仓风控」放在最后一期，与方法论 §5.4「减少大亏是第一步」、§6.4「持仓风控面板排第 3」及设计原则「先纪律后阿尔法」冲突。现改为最小风控前置、完整回测后置。  
> **任务级拆解与挂载点**见 [dev-plan-research-workbench.md](../dev-plan-research-workbench.md)；本节保留产品分期与验收口径。

### Phase 0 — 信息架构、对象模型与最小规则（1–2 周）

- 定 `Scope/Signal/Evidence/MetricDefinition/TradeCard` schema
- `/research` 空壳总览 + 跳转现有大盘/板块/个股（dashboard 路由树内）
- Agent 上下文协议打通；AI 输出校验层上线
- 定义止损线 / 集中度 / 违规计数的**规则口径**
- **清偿 §3.1.1 北向现网债**（改口径或下线 `stat.northbound`）

### Phase 1 — 大盘 + 板块 + 技术 + 最小风控（先有行情就能做）

- 市场温度计（资金项已按 §9.1 替换为可得数据；情绪阶段用本地 `ts:limit` + 宽度）
- 主线板块面板（boards + 资金流）
- 个股趋势/量价维（扩展 scanner），含涨跌停可成交约束
- 三套 Workspace 预设（短线桌可嵌 `/fupan` iframe，规则分仍走本地数据）
- **最小风控面板**：单票止损线、组合集中度、违规计数（§4.7 最小版；持仓来自 TradeCard / 导入）

**验收**：早盘 10 分钟能完成用例 1；每笔交易有止损线与集中度提示。

### Phase 2 — 财务 / 估值 + 扫描器 + 组合风控

- **先探测** Tushare `g_research` 权限；有则接财务，无则 PE/PB 分位 + 空态（§9.1）
- 质量+低估值模板扫描
- 六维 Scorecard 前三维 + 商业模式三态
- **完整组合风控面板**（暴露、相关性、回撤、再平衡提示）
- **一致性检查器**（§4.8；个股页头为主）

**验收**：自下而上用例 2 的财务/估值闭环（或明确降级空态）；组合暴露可见。

### Phase 3 — 事件情绪 + AI 简报 + 交易卡片复盘

- 统一事件时间线
- 新闻/公告 AI 聚类与方向（经输出校验层）
- 宏观/大盘/板块/个股一键 Brief
- 交易卡片与复盘报表（含基准对比、falsify_if 自动核对）

**验收**：新闻冲击用例 3；卡片字段完整率可统计；复盘含超额收益。

### Phase 4 — 回测与进阶

- 遵守 §9.2 的模板级回测
- **行为偏差检测**（§4.9）
- 样本外监控与策略说明书导出

## 13. 风险与非目标

**非目标（初期）**

- 自动下单 / 跟单
- 「必涨」预测模型包装成产品结论
- 替代券商专业终端的全部深度（Level2 全推等）

**风险与对策**

- AI 幻觉数字 → §5.4 输出校验层（证据绑定 + 数值校验 + 降级展示）
- 指标过拟合 / 前视 → §9.2 回测验证规范 + 规则版本化 + 实验性标记
- 信息过载 → 默认三套桌，六维按策略模板动态启用，高级因子折叠
- 数据源停更 / 权限不足 → §9.1 可得性矩阵 + 空态规则，禁止用旧数冒充实时
- 合规风险 → §5.4 每条 AI 输出持久化免责声明与延迟提示
