# 总览页 Portal 面板改造方案

> 范围：`/dashboard/` 总览（`apps/stock-dashboard/src/pages/Dashboard`）  
> 目标：可自定义布局的门户面板 + 更紧凑间距  
> 状态：**已拍板**（2026-10-26）  
> 执行计划：[`dev-plan-dashboard-overview-portal.md`](./dev-plan-dashboard-overview-portal.md)

---

## 1. 现状与问题

当前总览是**静态三段布局**，不是可编排门户：

| 区块 | 实现 | 问题 |
|------|------|------|
| 指数条 | `auto-fit` 卡片栅格，`gap: 12px` | 无法改尺寸/顺序；宽屏时一行 4+2 留白 |
| 行情统计 | `statsGrid` 6 张 KPI 卡 | 固定种类，不可增删 |
| 主区 | `1fr 1fr` 双列，列内纵向堆叠 | 无法左右互换、拉伸；`gap: 24px` 偏疏 |

代码侧特征：

- 区块写死在 `Dashboard.tsx`，无 `layout` 序列化
- 区块间距：页面级 `gap: 32px`，主栅格 `24px`，卡片内边距偏松
- 无编辑态、无拖拽、无面板目录、无布局预设

用户要的是：**看盘工作台**——一眼信息密度高、可按习惯拼版、缝隙尽量小。

---

## 2. 产品目标

### 2.1 必须做到

1. **12 列栅格门户**：每个面板占 `w` 列 × `h` 行，可拖拽位移、可拖拽缩放。
2. **尺寸有硬规则**：按面板类型约束 `minW/minH/maxW/maxH`，避免缩到不可读。
3. **自由组合**：从面板目录添加 / 移除；同类型可多实例（如两份榜单不同 Tab）。
4. **间隔收紧**：横向、竖向 gutter 明显小于现状（见 §5）。
5. **布局持久化**：本机 `localStorage`；支持「重置默认」「多套布局」。

### 2.2 非目标（一期不做）

- 服务端同步布局 / 跨设备
- 任意嵌套容器（portal 内再套 portal）
- 面板内可视化查询编辑器（Grafana 式 Query）
- 移动端精细拖拽编辑（手机只读 + 纵向堆叠）

---

## 3. 对标：主流 Portal 的共识

参考 Grafana / Datadog / PostHog / Notion Database / 交易终端工作区，成熟方案高度一致：

| 能力 | 行业共识 | 对本站建议 |
|------|----------|------------|
| 栅格 | **12 列**几乎成为默认 | 采用 12 列，勿自造 24/16 |
| 高度 | **行高单位**（row unit），非随意 px | `rowHeight ≈ 32–40px`，面板用整数 `h` |
| 编辑态 | **浏览 / 编辑**双模式，避免误拖 | 顶栏「编辑布局」开关 |
| 拖拽把手 | 仅标题栏可拖，内容区可点可选 | `draggableHandle: .widget-drag-handle` |
| 尺寸约束 | Catalog 声明 `default + min/max` | 每类面板入库，resize 时引擎强制 |
| 紧凑度 | 交易/监控类用 **tight density** | 默认 tight；可选 comfortable |
| 预设 | 默认布局 + 用户自定义命名 | 「默认看盘 / 资金流 / 自选优先」三套起步 |
| 响应式 | 桌面用完整布局；窄屏折叠或减列 | `lg=12 / md=6 / sm=1` 断点 |
| 持久化 | 布局 JSON 可序列化 | `{ i, x, y, w, h }` + widget config |

技术选型建议（与现栈契合：React 19 + Vite）：

- **布局引擎**：[`react-grid-layout`](https://github.com/react-grid-layout/react-grid-layout)（行业事实标准；PostHog / 大量 B 端门户同源思路）
- **不要**自写绝对定位拖拽；不要用纯 CSS Grid 假装可编辑

## 4. 栅格规则（已拍板）

### 4.1 列（宽度）

```
总列数 COLS = 12
单元宽度 = (容器宽 - (COLS-1)*gutterX) / 12
面板宽度 w ∈ [minW, maxW]，且 w 为整数
x ∈ [0, 12 - w]
```

**推荐宽度阶梯（用户心智 + 对齐）：**

| 语义 | w | 适用 |
|------|---|------|
| KPI / 迷你指标 | **2**（默认可改到 3–4） | 涨跌、涨停、成交额 |
| 半宽 | 6 | 自选、榜单、板块（并排） |
| 三分之二 | 8 | 主榜 + 侧栏组合 |
| 全宽 | 12 | 指数条、宽表、后续迷你图带 |

**对齐建议（软规则，编辑时可开「对齐辅助」）：**

- 优先落在 `x ∈ {0, 2, 3, 4, 6, 8, 9}`，减少「差 1 列」的锯齿
- 缩放时吸附到上述阶梯（可选，默认开）

### 4.2 行（高度）

```
rowHeight = 36px          # 基准行高（可配置 32 / 36 / 40）
gutterY   = 同 density    # 见 §5
面板像素高 ≈ h * rowHeight + (h-1) * gutterY
```

**推荐高度阶梯：**

| 语义 | h | 约高（rowHeight=36, gutter=8） | 适用 |
|------|---|-------------------------------|------|
| 矮 KPI | 2–3 | ~80–120px | 单指标卡 |
| 指数条 | 3–4 | ~120–160px | 多指数横滑/栅格 |
| 列表中 | 8–10 | ~320–400px | 自选、短榜 |
| 列表高 | 12–14 | ~480–560px | 热点板块、长榜 |
| 图表区（二期） | 10–16 | — | 分时/资金曲线 |

### 4.3 面板 Catalog 尺寸约束（一期）

把现有区块拆成**可注册面板**，约束如下：

| widgetType | 名称 | 默认 w×h | minW×minH | maxW×maxH | 说明 |
|------------|------|----------|-----------|-----------|------|
| `index.*`（6 个） | 上证/深证/创业板/科创50/沪深300/上证50 | **2×3** | 2×2 | **12×60** | 可拖满整行 |
| `stat.*`（6 个 KPI） | 涨跌/涨停/成交额等 | **2×3** | 2×2 | **12×60** | 可拖满整行 |
| `watchlist` | 自选股 | 6×10 | 2×4 | **12×60** | 行数随 h 裁剪 |
| `marketRanking` | 市场榜单 | 6×12 | 2×6 | **12×60** | Tab 可配置 |
| `fundFlowRank` | 主力净流入榜 | 6×10 | 2×4 | **12×60** | |
| `hotBoards` | 热点板块 | 6×12 | 2×6 | **12×60** | 行业/概念 Tab |
| `boardFundFlow` | 板块资金流 | 6×12 | 2×6 | **12×60** | |

> 原则：**min 保证可读**（标题 + 至少 3～5 行数据），**max 防止单块霸屏**；列表类高度变化只改「可见行数」，不改字号乱跳。

### 4.4 默认布局（迁移现状）

把现有视觉结构映射为一期默认 `layout`：

```
y=0   6×独立指数         x=0,2,4,6,8,10  w=2 h=3
y=3   6×KPI 各 w=2       x=0,2,4,6,8,10  h=3
y=6   watchlist          x=0  w=6  h=10
y=6   hotBoards          x=6  w=6  h=10
y=16  marketRanking      x=0  w=6  h=12
y=16  boardFundFlow      x=6  w=6  h=12
y=28  fundFlowRank       x=0  w=6  h=10
```

KPI 默认 **6 个 × w=2**（12÷6 齐整），已拍板；用户可删减或改宽。

## 5. 间距与密度（直接回应「间隔小一点」）

### 5.1 Density Token

| Token | tight（推荐默认） | comfortable（现状接近） |
|-------|-------------------|-------------------------|
| `gutterX` / `gutterY` | **8px** | 16px |
| 页面外边距 | 12px | 24px |
| 卡片内边距 | 10–12px | 16–18px |
| 卡片圆角 | 6px | 8–12px |
| 卡片阴影 | 弱或无（边框优先） | 现有 shadow-md |

现状：页面 `gap: 32px`、主栅格 `24px` → **建议默认改到 8px**，编辑态可临时加到 10px 方便抓取手柄。

### 5.2 视觉：从「卡片墙」到「瓷砖墙」

交易门户更吃密度时：

- 面板之间靠 **细边框 + 小 gutter**，少用大阴影悬浮
- 编辑态：面板描边高亮 + 半透明网格底纹（12 列虚线）
- 浏览态：隐藏 resize 手柄与网格底纹

### 5.3 与多面板 K 线页的关系

`/multipanel` 已定 `gap: 1px` 图墙风格。总览是**信息卡门户**，不宜 1px（会糊成一块大白板）。  
建议：**总览 tight=8px**；若未来加「图表墙」类面板，可对该类型单独用 1–2px。

## 6. 交互设计（最佳实践落地）

### 6.1 双模式

| 模式 | 行为 |
|------|------|
| **浏览**（默认） | 不可拖不可缩；标题栏可点进详情；列表可滚动点击 |
| **编辑** | 顶栏出现工具条；可拖、可缩、可删、可加；显示网格 |

入口：总览页右上角 **「编辑布局」** ↔ **「完成」**。  
快捷键（可选）：`E` 切换编辑；`Esc` 退出编辑。

### 6.2 编辑工具条

```
[完成] [添加面板 ▾] [布局预设 ▾] [密度: 紧凑|适中] [重置默认] [撤销]
```

- **添加面板**：右侧 Drawer / 居中 Modal，Catalog 卡片列表（图标 + 名称 + 简介 + 默认尺寸）
- **布局预设**：默认看盘 / 资金流优先 / 自选优先 / 我的布局 1…；支持「另存为」
- **撤销**：本地栈，至少 20 步（拖拽一次 = 一步）

### 6.3 拖拽与缩放

- **拖拽**：仅 `.widget-header` 左侧把手（`GripVertical`），避免和列表点击冲突
- **缩放**：右下角手柄；resize 过程实时吸附列/行；松手后 debounce 300ms 持久化
- **碰撞**：`verticalCompact: true`（向上填洞，Grafana 同款）；禁止随意重叠
- **锁定**：面板菜单「锁定位置」→ `static: true`

### 6.4 面板铬条（Widget Chrome）

```
┌─ [⠿] 标题                    [⋮] ─┐
│  内容区（overflow 自管）           │
└───────────────────────────────────┘
```

菜单 `⋮`：刷新、配置（如榜单 Tab）、锁定、复制、移除、跳转全页。

### 6.5 空态与溢出

- 无面板：大空态 +「添加面板」/「恢复默认」
- 高度不够：列表面板 **内部滚动**，不把整页撑破
- 宽度不够：表头列可隐藏次要列（如「所属行业」在 `w<5` 时隐藏）

### 6.6 响应式

| 断点 | 列数 | 编辑 |
|------|------|------|
| ≥1200px | 12 | 完整编辑 |
| 768–1199 | 6（布局自动折半或用独立 md layout） | 允许编辑 |
| <768 | 1 列堆叠 | **只读**，提示「请在桌面编辑布局」 |

## 7. UI 建议（贴合现有 A 股看板）

保持现有 Zinc 极简 + 红涨绿跌，只改「编排层」：

1. **浏览态**几乎看不出「门户框架」——只是更密、更齐的面板墙。
2. **编辑态**才出现：虚线网格、把手、resize 角、工具条主色按钮。
3. KPI 面板统一数字区高度，避免六张卡高低不一。
4. 指数面板：宽屏一行 6；缩到 `w=6` 时两行或横滑（二选一，建议两行）。
5. 减少卡片进场动画幅度（现状 `translateY(20px)` 在拖拽场景会晕）；编辑态关闭 enter 动画。

## 8. 数据与配置模型

### 8.1 Layout Item

```ts
interface PortalLayoutItem {
  i: string;          // 实例 id，与 React key 一致
  x: number;          // 0–11
  y: number;
  w: number;
  h: number;
  minW?: number;
  minH?: number;
  maxW?: number;
  maxH?: number;
  static?: boolean;   // 锁定
}
```

### 8.2 Widget Instance

```ts
interface PortalWidgetInstance {
  id: string;                 // = layout.i
  type: PortalWidgetType;     // catalog key
  title?: string;             // 覆盖标题
  config?: Record<string, unknown>;  // 如 rankingTab: 'rise'
}
```

### 8.3 持久化 Key

```
stock-dashboard:overview-portal:v1
  → { version, density, activePresetId, presets: [{ id, name, layout, widgets }] }
```

迁移：无本地数据时写入「默认看盘」预设；版本号升级时跑 migrate。

## 9. 架构落点（实现侧）

```
pages/Dashboard/
  Dashboard.tsx              # 薄：模式切换 + PortalCanvas
  portal/
    PortalCanvas.tsx         # react-grid-layout 壳
    PortalToolbar.tsx
    WidgetChrome.tsx
    widgetCatalog.ts         # 类型、默认尺寸、组件映射
    defaultLayouts.ts
    usePortalLayout.ts       # load/save/debounce/undo
    widgets/
      IndicesWidget.tsx      # 从现有 JSX 抽出
      StatBreadthWidget.tsx
      WatchlistWidget.tsx
      ...
```

原则：

- **现有数据拉取逻辑尽量上提或保留 hooks**，Widget 只消费 props/context，避免每个面板各拉一遍全市场。
- 指数 / 自选 / 行情广度 / 资金流仍用现有轮询策略；隐藏的面板可暂停其专属请求（二期优化）。

依赖新增：`react-grid-layout` + 类型包；样式引入其 CSS，再用本地 token 覆盖 margin。

## 10. 分阶段交付

### Phase 0 — 密度快修（已拍板：先做）

- 总览 `gap`：32/24 → **8/8**
- 卡片 padding 略收；主栅格保持结构不动  
→ 立刻满足「间隔小一点」，不阻塞门户改造。

### Phase 1 — 可编辑门户 MVP

- 12 列 + rowHeight + Catalog 约束
- 编辑/浏览双模式；拖拽、缩放、增删
- 默认布局 ≈ 现状；localStorage 持久化
- 一套「重置默认」

### Phase 2 — 预设与体验

- 多套命名预设；撤销栈；面板锁定
- 密度切换；窄屏只读策略
- 列表行数随 `h` 自适应

### Phase 3 — 增强（可选）

- 迷你分时 / 资金曲线 Widget
- 自选条、涨停日历等新类型
- 导出/导入布局 JSON；账号级同步

## 11. 拍板（不可再议，除非产品变更）

| # | 议题 | 决定 |
|---|------|------|
| 1 | 布局引擎 | **`react-grid-layout`** |
| 2 | 列数 / 行高 | **12 列 / `rowHeight=36`** |
| 3 | 默认 gutter | **8px**（tight）；comfortable=16px 作 Phase 2 选项 |
| 4 | KPI 默认宽度 | **`w=2`，默认放满 6 个 KPI** |
| 5 | 碰撞策略 | **垂直 compact，禁止重叠** |
| 6 | 一期持久化 | **仅 `localStorage`**（key 见 §8.3） |
| 7 | 手机 | **只读堆叠**，不提供拖拽编辑 |
| 8 | Phase 0 | **先做间距快修**，再上门户 MVP |

开发任务与勾选清单见 [`dev-plan-dashboard-overview-portal.md`](./dev-plan-dashboard-overview-portal.md)。

## 12. 成功标准

1. 用户可在 1 分钟内完成：改面板大小、换位置、加一个榜单、保存后刷新仍在。
2. 默认布局信息密度明显高于现状，且无内容被裁切到不可用。
3. 浏览态零误拖；编辑态手柄清晰。
4. 面板间距视觉上 ≤ 现状的约 1/3（24–32px → 8px）。
5. 不破坏现有数据正确性（指数走 index、涨跌色、跳转 `/s/:code` 等）。
